# Phase 3 — Requirements Engineering

## 1. MVP Scope

نسخه اول محصول باید تمام حوزه‌های اصلی عملیات مالی شرکت را پوشش دهد:

- حسابداری عمومی
- فروش
- خرید
- دریافت و پرداخت
- بانک
- صندوق
- چک
- انبار
- هزینه‌ها
- حقوق و دستمزد
- بیمه
- مالیات و صورتحساب الکترونیکی
- دارایی ثابت
- گزارش‌های مالی
- کنترل و مغایرت‌گیری
- مدیریت اسناد
- Agentهای تخصصی

اما MVP برای یک **شرکت بازرگانی ساده** تعریف می‌شود.

بنابراین:

> Breadth بالا، Depth کنترل‌شده.

یعنی ماژول‌ها از ابتدا وجود دارند، ولی قابلیت‌های پیچیده و تخصصی هر ماژول به نسخه‌های بعد موکول می‌شوند.

---

# 2. اصول اصلی محصول

## Requirement R-001 — Agent-First Workflow

هرجا کاری تکراری، قابل‌قاعده و قابل‌کنترل است، سیستم باید بررسی کند آیا Agent می‌تواند آن را انجام دهد.

---

## Requirement R-002 — Human Approval

Agent نباید در MVP عملیات مالی مؤثر را بدون تأیید کاربر اجرا کند.

الگوی عمومی:

```text
User Request
     ↓
Agent Analysis
     ↓
Action Plan
     ↓
User Review
     ↓
Approve
     ↓
Execute
     ↓
Validate
     ↓
Audit
```

---

## Requirement R-003 — Explainability

Agent باید قبل از اجرا مشخص کند:

- چه چیزی فهمیده است.
- چه کاری می‌خواهد انجام دهد.
- روی چه اطلاعاتی تصمیم گرفته است.
- نتیجه احتمالی چیست.
- چه مواردی نامطمئن هستند.

---

## Requirement R-004 — Full Auditability

هر عملیات انجام‌شده توسط Agent باید قابل ردیابی باشد.

حداقل:

- چه کسی درخواست داد؟
- کدام Agent انجام داد؟
- چه داده‌ای استفاده شد؟
- چه پیشنهادی تولید شد؟
- چه زمانی تأیید شد؟
- چه کسی تأیید کرد؟
- چه عملیاتی اجرا شد؟
- نتیجه چه بود؟
- چه چیزی تغییر کرد؟

```text

 ↓

```

عملیات ارسال به سامانه‌های بیرونی باید به‌صورت Integration مستقل طراحی شود.

در حال حاضر سازمان تأمین اجتماعی انجام فرایند ارسال لیست و پرداخت حق بیمه را از طریق سامانه خدمات غیرحضوری خود ارائه می‌کند.

# 13. Tax Requirements

### Tax Calculation / Accounting

با توجه به تغییرپذیری مقررات، جزئیات قانونی باید قبل از Release مربوطه به‌صورت جداگانه Validation شوند و نباید در هسته عمومی محصول Hard-code شوند.

# 15. Reconciliation Requirements

مغایرت‌گیری باید یکی از Capabilityهای اصلی سیستم باشد.

حداقل:

```text
Bank ↔ Accounting

Payment ↔ Invoice

Receipt ↔ Invoice

Purchase ↔ Inventory

Sales ↔ Inventory

Customer ↔ Receivable

Supplier ↔ Payable
```

سیستم باید:

1. موارد قابل تطبیق را پیشنهاد دهد.
2. موارد بدون تطبیق را پیدا کند.
3. موارد مشکوک را مشخص کند.
4. موارد تکراری را پیشنهاد دهد.
5. اجازه بررسی انسانی بدهد.

# 17. Agent Safety Rules

Agent نباید:

- عملیات مالی مؤثر را بدون تأیید انجام دهد.
- داده‌ای را که اطمینان کافی درباره آن ندارد، قطعی تلقی کند.
- اطلاعات را بدون ثبت منبع تغییر دهد.
- تاریخچه عملیات را پاک کند.
- بدون Permission مناسب عملیات اجرا کند.

# 19. Non-Functional Requirements

## NFR-001 — Speed

هر عملیات تکراری باید با هدف کاهش زمان انجام شود.

برای هر Feature زمان:

```text
Manual
vs
System
vs
Agent
```

اندازه‌گیری خواهد شد.

## NFR-002 — Consistency

خروجی‌های سیستم و Agent باید در شرایط مشابه، رفتار پایدار و قابل کنترل داشته باشند.

## NFR-003 — Auditability

عملیات مالی باید قابل ردیابی باشد.

## NFR-004 — Security

اطلاعات مالی و کاربران باید دسترسی کنترل‌شده داشته باشند.

## NFR-005 — Reliability

خطا در اجرای Agent نباید باعث ثبت ناقص یا مخدوش عملیات مالی شود.

## NFR-006 — Recoverability

برای عملیات مالی باید امکان شناسایی و بازیابی خطا وجود داشته باشد.

## NFR-007 — Extensibility

نوع کسب‌وکار نباید به‌صورت Hard-coded در هسته محصول قرار گیرد.

# 20. MVP Exclusions

در MVP:

- اتصال مستقیم بانک نداریم.
- Integrationهای عمومی و Marketplace نداریم.
- اتوماسیون کاملاً خودمختار Agent نداریم.
- HR کامل نداریم.
- CRM نداریم.
- Manufacturing نداریم.
- Advanced Consolidation نداریم.
- قابلیت‌های بسیار تخصصی صنایع مختلف نداریم.

این موارد ممکن است در نسخه‌های بعد اضافه شوند.

---

# 21. MVP Quality Checkpoints

برای هر Capability حداقل این موارد سنجیده می‌شوند:

### Speed

آیا زمان انجام کار نسبت به روش دستی کمتر شده؟

### Consistency

آیا نتیجه در شرایط مشابه پایدار است؟

### Accuracy

آیا خروجی درست است؟

### Exception Rate

چه مقدار از موارد نیازمند اصلاح انسانی‌اند؟

### Approval Rate

چه درصدی از پیشنهاد Agent مستقیماً قابل تأیید هستند؟

### Traceability

آیا می‌توان فهمید Agent چه کاری انجام داده و چرا؟
